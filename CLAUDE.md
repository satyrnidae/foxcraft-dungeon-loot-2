# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Minecraft 1.19 datapack (`pack_format` 10) adding custom "dungeon loot" items, plus a companion resource pack in `texturepack/`. Functions are written in [MC-Build](https://mcbuild.dev/docs/) (`.mc` / `.mcm`) and compiled into plain `.mcfunction` files.

## Build and run

- `npm i mc-build` installs the compiler (dependency in `package.json`); run `mcb` in the repo root to compile `src/` into `data/`. `mcb.ps1` is a watch/restart loop around it.
- `build.ps1` (PowerShell + 7-Zip) zips the datapack into `.build/<baseArchiveName>-<version>[+dev].zip`, then runs `texturepack/build.ps1` to zip the resource pack. `exclude.txt` keeps `src/`, `texturepack/`, scripts, and config out of the datapack zip.
- There are no tests or linters. Verify changes by loading the pack in a Minecraft 1.19 world.
- Version lives in two places that must be kept in sync: `config.json` (`mc.version`, used by templates and the zip name) and `pack.mcmeta` (`meta.version` and `meta.changelog`). `config.json` `mc.dev: true` enables dev-only code (e.g. re-enabling the `satyrn.fdl.loot.variant` trigger every tick via `!IF(config.dev)`).

## Source vs. generated output

- `src/` is the source of truth for **functions**. `data/foxcraft_dungeon_loot/functions`, `data/minecraft/tags/functions/load.json` and `tick.json` are generated by `mcb` and gitignored. Never edit them.
- Everything else under `data/` (loot tables, predicates, advancements, item modifiers, function tags in `tags/functions/`, `data/global`) and `texturepack/` is hand-written JSON and is committed.
- `src/foxcraft_dungeon_loot.mc` defines the top-level `load`, `tick`, `uninstall`, and `update_scoreboards` functions. Config values are templated with `<%config.x%>` (see `config.json`).
- `src/macros.mcm` holds shared macros (`break_item`, `random`, `remove_enchantment`). Files opt in with `import ../macros.mcm`.

## Architecture: event-bus via function tags

Core tick/load logic is deliberately decoupled from items. `load`/`tick`/`uninstall` call function tags such as `#foxcraft_dungeon_loot:on_load`, `on_tick`, `on_uninstall`, `on_fall`, `on_snowball_used`, `on_warped_fungus_used`, `on_spider_eye_eaten`, `on_block`. These are hand-maintained JSON lists in `data/foxcraft_dungeon_loot/tags/functions/`.

- Each item has `src/foxcraft_dungeon_loot/items/<item>.mc`; each `function x` inside compiles to `items/<item>/x`. Items implement whichever hooks they need (`on_load`, `on_tick`, `on_snowball_used`, ...).
- **Adding or removing an item hook means also adding/removing its `foxcraft_dungeon_loot:items/<item>/<hook>` entry in the matching tag JSON**, otherwise it never runs.
- `src/foxcraft_dungeon_loot/events.mc` turns vanilla stats and predicates (fall distance, used snowball / warped fungus on a stick, ate spider eye, blocked with shield) into those events. Item-specific events are only dispatched to players matching `predicates/events/process_*` (e.g. holding an event-enabled item), which is how the pack stays cheap on slow CPUs. New events need an objective, a predicate, a dispatch in `events.mc`, and a tag file.
- Items use scoreboards/tags prefixed `satyrn.fdl.*`. Periodic work uses self-rescheduling `schedule function ... Nt` clocks started from `on_load`.

## Items and loot

- Each custom item is identified by an integer NBT `DungeonLootId`, which must be unique (master list is a Google Sheet linked in `README.md`).
- Item definitions are loot tables in `data/foxcraft_dungeon_loot/loot_tables/items/<rarity>/...` (common, uncommon, rare, epic, mythic), with per-rarity `*_grab_bag.json` tables. Variants (e.g. chainsaw diamond/netherite upgrade) are selected by setting the `satyrn.fdl.loot.variant` score before `loot give`, then resetting it.
- `data/foxcraft_dungeon_loot/item_modifiers/` and `advancements/items/` hold per-item modifiers and use-detection advancements. `advancement revoke @a from foxcraft_dungeon_loot:items` runs on load to reset them.
- `data/minecraft/loot_tables` overrides vanilla tables to inject the loot.

## Trades

`src/foxcraft_dungeon_loot/trades*.mc{,m}` and `trades/` implement custom Wandering Trader offers. A trade **index** is built into storage `foxcraft_dungeon_loot:trades` by spawning loot-table items in a force-loaded chunk of the End (264, 64, 264). It runs over multiple ticks (`wait_for_chunk` then `build`), and `scheduled_tick` only starts once it's populated. Recipes are appended in `trades/index.mc` using the `set_*_from_loot` macros in `trades.mcm`; the position in the index (the `Trade Index N` comments) matters because offers are selected by index.

## Scoreboards

`config.json` `scoreboardsVersion` is compared against `#version` in `satyrn.fdl.internal`. When a scoreboard objective is renamed or its type changes, bump it and add the removal to `update_scoreboards` in `src/foxcraft_dungeon_loot.mc`. Every objective added in an `on_load` needs a matching removal in `on_uninstall`.

## Resource pack

`texturepack/` is a separate pack (own `pack.mcmeta`, built by `texturepack/build.ps1`) with models, textures, sounds, and shaders. Custom music-disc assets are gitignored; credits and licenses are in `README.md`.
