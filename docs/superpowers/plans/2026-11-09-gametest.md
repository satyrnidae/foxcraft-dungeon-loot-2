# Gametest Harness and Wave 1 Scenarios Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `npm run gametest` runs headless gametest scenarios for the pack on a 26.3 server jar and prints PASS/FAIL per scenario.

**Architecture:** Port of `~/sandbox/furnace_train/gametest`: a second mc-build project in `gametest/mc` (namespace `fdl_test`, never built into `data/`), a generator that writes one structure, environment and test instance per manifest entry, and a runner that assembles the packs, runs `net.minecraft.gametest.Main` and parses `report.xml`. Scenarios share one force-loaded arena and run in non-overlapping windows on a global tick clock.

**Tech Stack:** Node, mc-build 4.2.0 (the pack's own), Mojang server jar 26.3, Java 25.

**Spec:** `docs/superpowers/specs/2026-11-09-gametest-design.md`. Read `~/sandbox/furnace_train/gametest/{run,generate,fetch-server,tests}.js` and `mc/src/train_test.mcb` (regions Library and Gametest poll functions) first, most files are ports.

## Global Constraints

- Pack format 121, Minecraft 26.3, server jar only, Java 25 via `GAMETEST_JAVA`, `java` on this machine is 22.
- `fdl_test` never lands in `data/`; `run.js` fails the run if `data/fdl_test` exists.
- Gametest pack ids: structure, environment and instance are `fdl_test:<id>`, test filter default `fdl_test:*`.
- Scoreboard objectives `fdl_test` (dummy) and `gt.age`; `#ok fdl_test` is 1 before each step, a step fails by setting it to 0.
- Arena origin marker at 100.5 64 100.5, tagged `tt` and `tt.origin`; everything else is placed relative to it and tagged `tt`.
- Chance rolls are not tested: effect functions are called directly. No scenario may need a player.
- Writing style per `~/.claude/CLAUDE.md`: American English, plain ASCII, terse comments.
- Commits signed, one scope each.

## Review Focus

- Leftover entities or effects from one scenario leaking into the next window: `lib/cleanup` kills `tt` entities and every scenario clears effects on its mobs; the aura scenario, first in the group, asserts no `tt` entity but the origin exists before it spawns its own.
- A stale or broken build passing silently (mcb exits 0 on compile error): Task 1 makes `run.js` grep the output, tested by breaking a function.
- Live pack ticks acting on test entities, for example `item/mythic/hammer_of_sol/on_tick` and the other `on_tick` tag members: Task 4 asserts the expiry only fires inside its window.
- Loot tables that need a context beyond `loot spawn` position, or that roll nothing: Task 5 reports each table that yields no item rather than skipping it.
- `uninstall` removing objectives other windows still need: Task 6 puts it in the last window, then reloads.
