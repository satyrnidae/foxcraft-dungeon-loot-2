# books

Book loot generator, built from markdown in `src/books`. Dev utilities, not part of the datapack zip.

## generate_previews.mjs

`npm run previews` runs the generator, `tests/unit/books.test.mjs` and then only `BookRender`, which draws every page to `tests/.cache/books`. `--no-tests` skips the tests, `--no-download` never fetches the client jar, `--scale N` sets the pixels per GUI pixel. `--book <author>/<title>` rebuilds and redraws only that book, as `chickenny/brewing_potions`, and can be repeated. A bare title works only while no other author has a book of that name, else the run stops and lists the authors: only its loot is rewritten, only its folders under `tests/.cache/books` are replaced, and the other books and their pages stay as they are. Run `npm run previews -- --book chickenny/brewing_potions`. A page with `||obfuscated||` text comes out as an animated PNG, 15 frames at 5 fps, under the same `page_NN.png` name.

## viewer.mjs

`npm run viewer` serves `tests/.cache/books` on `http://127.0.0.1:4173` and opens it; `--port N` changes the port, `--no-open` skips the browser. No dependencies. Run `npm run previews` first, the viewer exits when the cache is empty. Each book is its own item icon with its raw id under it, resolved from the `item_model` the generated modifier sets through the item definition and model to the texture, the resource pack's first and the client jar's under it, with the enchantment glint over books that are written books, grouped by author folder, with a locale select and a name filter. Text with a click or hover event, a `[text](target "hover")` or an `<a on_click on_hover>`, gets an entry in a `page_NN.links.json` beside its page from `BookRender`, the rectangles in GUI pixels with the action and value, and a `page_NN.hover_K.png` tooltip drawn for each hover text. The reader lays areas over the page image from it: `open_url` opens the link in a new tab, `change_page` turns to that page, `copy_to_clipboard` copies and says so, `run_command` and `suggest_command` only show their command, and a hover shows its tooltip image at the pointer. The tooltip shows the generation line the book sets, such as Tattered. Hovering shows `tooltip.png`, the item tooltip `BookRender` draws beside the pages from the generated modifier and loot table: name, author and generation lines, lore and the rarity line, in the locale. Clicking opens the pages with arrow keys, Esc and a chat filtering toggle for books with filtered pages; the URL hash `#<locale>/<group>/<id>/<page>` links a page. The icon is taken from the client jar in `tests/.cache/mc` into `tests/.cache/viewer` the first time. The page, script and styles are in `viewer/`, the index and icon code shared with the site build in `viewer_lib.mjs`. `BookRender` writes an empty `page_NN.heading` file beside a page with a line of only underlined text outside a link, and the viewer marks those pages on a row above the page slider. Headings of level 5 and 6 are not underlined and go unmarked.

## build_site.mjs

`npm run site` writes the viewer as a static site to `.build/site` (`--out DIR` for another place): the `viewer/` files, `icon.png`, `books.json` and the rendered pages under `files/`, all with relative URLs. `.github/workflows/pages.yml` runs it after `npm run previews -- --no-tests` on every push to `main` and deploys it to GitHub Pages; the repo needs Settings > Pages > Source set to GitHub Actions. The site holds the vanilla book texture, tooltip frame and icon from the Mojang client jar, so keep it to a repo you are fine publishing those from. The workflow first runs `site_books.mjs`, which turns `THIRD_PARTY.md` and `README.md` into the sources `src/books/en_us/site/third_party_notices.md` and `about.md` (gitignored, links kept as markdown links), so the site has Third Party Notices and About books that no local or release build does. They are not in the grid, buttons in the header, About and Third Party Notices at the upper right after the book count, open them. Books with `debug: true` are in it when `mc.dev` is true in `config.json`.

## book_loot_gen.js

Writes written book loot from markdown. `mcb build` runs it through `src/foxcraft_dungeon_loot/books.js`; run it by hand with `node scripts/books/book_loot_gen.js`, add `--check` to write nothing and fail when output is stale, or pass source files to limit the modifiers.

### Layout

- Sources: `src/books/<locale>/<id>.md` or `src/books/<locale>/<group>/<id>.md`, for example `src/books/en_us/unattributed/palomina_and_the_demon_lord.md`. The group folder, such as the author, is only for sorting and is not part of the id, so ids stay unique across groups.
- `en_us` is the reference. It writes `data/foxcraft_dungeon_loot/item_modifier/random_loot/book/<generatedDirectory>/<id>.json` and `loot_table/item/random_loot/book/<generatedDirectory>/<id>.json`, both gitignored. Files in those `generated` folders without a source are deleted, anything beside them is left alone. A book with `debug: true` is only generated when `config.json` `mc.dev` is true. Adding the book to a random loot pool stays manual, or point the pool at the loot table `item/random_loot/book/<generatedDirectory>/random_book`, or at `item/random_loot/book/<generatedDirectory>/random_book`. `random_book` rolls one of all generated books and `random_<rarity>_book` one of a rarity, for common to cursed. A `debug: true` book is left out of all of them. A rarity without a book is an empty table that drops nothing. Loot tables have no tags, and those names are not usable as book ids.
- Every locale writes its text to `texturepack/assets/<generatedDirectory>/lang/<locale>.json` under `book.foxcraft_dungeon_loot.<id>.*`. The whole file is generated, so hand-written keys go in another namespace's lang file. A translation is the same markdown in another locale folder. There is one book, built from the `en_us` file, and a translation only gives it lang entries. Every locale has its pages cut on its own, each page filled to 14 lines, so a language that needs more or fewer pages than the others does not leave partly empty ones; the book has the pages of the longest locale and a shorter one ends in empty pages. A page of the book lists the spans of every locale that has them on it, and the lang entry of each locale for the page uses the ones it needs. For that the translation needs the same spans, in the same order, as the `en_us` file, with the same styles, though the text a `<filter>` shows instead may be formatted differently; its text needs nothing else, and the `<br>` breaks may differ. A translation whose spans differ is left out, with a warning, and shows English. A page never ends inside a `<filter>` span, and it has to fit in 14 lines in the filtered reading too.
- Arabic is drawn wider than the game measures it: the splitter counts the plain letters, the renderer draws their joined forms and ligatures. So a text with Arabic in it is cut into lines by the generator, which measures both ways and puts a newline at each wrap, and the game then has nothing left to wrap. The forms come from `scripts/books/arabic_shaping.json`, made from the game's own shaper by `tests/java/ArabicShapingTable.java`; the Java step of `tests/run_all.mjs` runs that class on every run, and when the file is not what the game's shaper gives it writes it again and fails, so run again. The lam-alef pair is written out as its ligature first, because the shaper makes one glyph of the two, and the styles the game keeps for the line then land a glyph early on everything after it: the padding after a ligature would be drawn in the font of the text. A `<filter>` span can read wider filtered than raw, and the cuts and the padding are made once for both readings: the lines count the extra pixels of the filtered text after the span, so a line that would overflow in either reading wraps before the span, and the padding of an aligned line that has such a span is a filter span of its own, with the padding the filtered reading needs, so the line ends at the same edge in both. `BookRender` fails a drawn line wider than the page, in the raw and in the filtered reading. The game draws every line from the left edge, also in right to left languages, so those get their padding from the generator, see `align` in `src/books/README.md`: the padding of a line that reads right to left goes after its text, behind a right to left mark (`‏`, blank in `font/padding.json`), where the game draws it at the left.
- Page text is `translate` with the English as `fallback`, as the key the resource pack translates. The books need the resource pack for their fonts anyway. A span inside a page is a `%1$s` argument with its own key.
- Dev builds get `/trigger give_book_<id>_by_<author>` (`give_book_<id>` for `unattributed`, `give_debug_book_<id>` for `debug`) for every en_us book, from `give.js`. A release build adds none, `/function foxcraft_dungeon_loot:give/give_book_<id>_by_<author>` stays.

### Source format

The authoring guide, with the tall font and hyphenation rules and the `<span>` tag, is `src/books/README.md`. What follows is the reference.

```
---
title: Book title, or SNBT text component
displayTitle: Item name, when it is longer than the 32 characters of a title
author: Name
rarity: common|uncommon|rare|epic|mythic|cursed
styles: { body: { font: foxcraft_dungeon_loot:pixellated_elegance/regular } }
model: foxcraft_dungeon_loot:random_loot/written_letter
data: {DungeonLootId:87,DungeonItem:1b}
writable: false
debug: true
generation: 0|original, 1|copy, 2|copy of a copy, 3|tattered
lore:
  first lore line, wrapped by hand
  second lore line
---

Text flows over the pages by itself. A newline is a line break,
so this is the second line, and a blank line is an empty one.

A long line wraps on its own, and the page changes after 14 lines.
---
This starts a new page.
```

- A `<br>` is a manual page break, alone on a line or in the middle of one. Everything else is cut into pages automatically: a page holds 14 lines of 114 pixels, a line wraps after its last space, and a page never starts with an empty line. A line that starts at a newline keeps its indentation, a line that starts at a wrap loses its leading spaces, and every line loses its trailing spaces. A trim can change where text wraps, so the layout is redone after each cut until no line needs one.
- A line of only `---` is a horizontal line, see `horizontalLine` in the generator and `src/books/README.md`.
- Spans do not reach across a page break, close them first. A `<br>` inside a fence or an inline code span is not a break.
- Title is plain text, at most 32 characters. A plain `title` and `displayTitle` read `\n`, `\t`, `\\` and `\uXXXX` as the characters, so an item name can have a line break; another backslash stays as typed, and an SNBT title has its own escapes. `<filter as="Darn Book">Damn Book</filter>` in it sets the chat-filtered title, the same tag as in the text. The filtered title is limited to 32 characters too, and an SNBT title cannot have one. A title in SNBT also sets `custom_name` and its plain text becomes the book title. A book with a `rarity` gets the item name in the color of the rarity, not italic, like the other items of the pack; the item name has no filtered side, so it uses the filtered title when there is one; an SNBT title keeps its own colors and styles over it. A book without a rarity keeps the name the game derives from the title.
- Generation is optional: `0` or `original`, `1` or `copy`, `2` or `copy of a copy`, `3` or `tattered`, saved as the `generation` of `minecraft:written_book_content`. It defaults to original, which is left out of the component. A tattered book cannot be copied. A translation inherits it from the `en_us` book.
- Model is optional, an item definition id saved as `minecraft:item_model`; `.json` is dropped and a bare path gets the pack namespace.
- Data is optional, an SNBT compound written as `minecraft:set_custom_data` in its string form, so byte and int suffixes survive.
- Writable is optional, `true` makes a `minecraft:writable_book` with plain string pages: no formatting, hyphenation, author or lang entries, and the title is the item name.
- The font of the whole text is `styles: { body: { font: ... } }`, a `<font face>` inside still wins; the old `font:` key still works, with a deprecation warning. It is measured for the layout, so the page fit follows it. Title and lore keep the default font. Fonts listed in `scripts/fonts/font_kerning.json` get their spacing adjusted with padding glyphs, see the fonts README.
- Rarity sets the `rarity` byte and appends the `Rarity: ` lore line after the lore, colored like the rest of the pack, through the shared modifier `item_modifier/rarity/<name>.json` that the generated loot table lists in its entry; the lore of the book is inserted above it. Lore lines stay within 44 average characters, 226 pixels, and the script warns about a line over that or one that stops early.
- Formatting: `**bold**`, `*italic*` or `_italic_`, `__underlined__`, `~~strikethrough~~`, `||obfuscated||`, `#` to `######` headers with an empty line under them, each level with its own look and `#` centered, see `src/books/README.md`, `\*` to escape, `\uXXXX` or `\u{X..}` for a code point. Stacked formatting is one component, nested formatting uses `with`.
- List items (`- ` and `1. `) hang: a wrapped line starts under the item text, not the marker. Numbers in one list take the width of the widest, so `1. ` gets padding after it once a `10. ` shows up, anywhere in the list. Indented items are their own lists. Not done in right to left locales.
- A line in a code block of 10 or more `-` or `=` and nothing else is a horizontal line of that character in the code font, as wide as the page, so a pasted license divider does not wrap. It is the same as `<style font="foxcraft_dungeon_loot:pixel_mono" char="=">---</style>`: `font` and `char` on that tag give a `---` line its own glyph.
- `inline code` and fenced code blocks, three backticks on their own line, are set in `foxcraft_dungeon_loot:pixel_mono`. Their text is literal, nothing in it is markup, a block keeps its indentation and a `#` in it is not a heading. A backtick without a closer on the line stays a backtick. A block does not reach across a page break. A block with a language after the fence is colored: `mcfunction`, `json`, `javascript` or `js`, `bash` or `sh`, `python` or `py`, `yaml` and `java`. A block with none, or one that is not in that list, stays plain. Prism does the lexing, a dependency; mcfunction has a tokenizer of its own in `scripts/books/highlight.js`, which also holds the colors. The code itself is written as plain text components, not translatable ones. A block is one `with` entry of its page, a translate component with a lang key of its own for the template that joins the pieces, so the text around it has a single `%n$s` for all the code. `code_block_test_book` shows every language.
- Inline code with a type word right after the closing backtick, and no letter or digit after the word, is that type instead of code; whatever follows stays text, a space too except after `pad` and `drop`, which drop one. `INLINE_TYPES` in `book_loot_gen.js` maps each word to a function from the code to the nodes it stands for, so a new type is one entry, and `INLINE_EATS_SPACE` lists the types that drop the space. `drop` is moved after layout by `applyDropCaps`, which puts the cap at the start of the line after its padding. `` `n`pad `` is `n` pixels of padding glyphs, see `src/books/README.md`; `padWidth` reads the number and rejects one past 113 forwards or 114 backwards. `` `n`tally `` is tally marks in `foxcraft_dungeon_loot:tallies` (`texturepack/.../textures/font/tallies.png`, a tick and a cross glyph): `tallyNodes` sets groups of four ticks and the cross stepped back to its middle with the padding font, and breaks the run into lines of its own when the groups are wider than the page.
- A fence with the language `music` is staff notation instead, drawn by `scripts/music/music.js` in `foxcraft_dungeon_loot:staff_notation`: one staff line a block, stretched or squeezed to the page width and broken at bars only when squeezing is not enough. Each line is two literal spans, the staff in grey padded back to its start and the notes in black, every glyph set at its pixel with the padding font. The notation is in `src/books/README.md`.
- `<font color="gray" face="minecraft:illageralt" shadow="#80ff0000">text</font>`: color is a name or `#rrggbb`, face is the font, shadow is `#aarrggbb` for `shadow_color`.
- `<a on_click='{action:copy_to_clipboard,value:"text"}' on_hover='{action:show_text,value:"tip"}'>text</a>`: both attributes take SNBT click and hover events. A plain `href="https://..."` makes an `open_url`.
- `<filter as="darn">damn</filter>`: the chat-filtered text. Players with chat filtering on see `as` in its place, everyone else sees the content. `as` takes the same markdown as the text and inherits the formatting around the span. Pages are cut by the raw text and the filtered page follows, so both have the same page count. A page with no difference stays a plain component. Warns when a filtered page runs over 14 lines or a page break falls inside a span. An old `<id>_filtered.md` is ignored with a warning.

### Page fit

Widths come from the font of each glyph, so `<font face>` changes how much fits. Bold is a pixel wider. A page that would pass the editor limit of 1024 characters gets a warning, as does a book over 100 pages and a font that is not defined anywhere.
